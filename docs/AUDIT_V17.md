# Ver.17.0の監査と統合方針

基準：添付GNX_Ver17_0(1).zip、SHA-256 `b90d49b8bf8c54f1f88ad60c66be2d29ccb8644e7a2240720aba5be4a8ddc51e`（正確な照合値はCOMPATIBILITY_V18.md参照）。tests/legacy147.jsonに旧データ全体、tests/baseline17.jsonにZIP全ファイルのSHA-256を保存。

## 検出結果

- 147記事、211チェック。記事/チェックIDの重複なし。
- 収集候補の旧72記事を抽出。DLC8単位は本編と分離。
- アイテム取得と鈴玉を渡す行動が別チェック。収集の分母には取得だけを採用。
- 霊クラゲの遺灰、指殺しの刃、暗月の指輪に、同じ品の明示的な取得チェックがNPCと収集記事に存在。各2IDを削除せず名寄せ。独立した収集進捗は増設しない。
- ネフェリの「円卓で報酬を確認した」と武具塊のお守りの取得は意味が完全には同じでないため、自動で結び付けない。今後の個別再検証対象。
- 通常版の黄金樹の恩寵を伝説の+2に流用しない。
- 旧「確認した」チェックは所持確認と断定できない。収集画面で継承の意味を表示し、所持の再確認を利用者に委ねる。
- 盾、部位別防具、結晶雫、製法書、石剣の鍵全地点などが不足。分類だけ用意し、未確認の攻略記事は作らない。

## 実装単位

既存147記事・タスク配列は変更せず、新規20記事を末尾追加。collectionsは参照用の追加フィールドで、進捗保存形式ではない。既存カテゴリを再分類・移動せず、収集専用taxonomyで盾/鈴玉/地点などを管理する。stable collection ID、記事ID、checkIds、itemFamily、occurrences、gameScope、sourceIds、属性ごとの未確認nullを持つ。

別名チェックは読み取り時にORとして表示。初回表示/フィルター/クラウド読込で状態を自動修正しない。明示的なチェック操作でだけ同時更新する。数量や周回を既存booleanから推測しない。防具一式から部位の所持を派生させない。

## 台帳の限界

data/collection-ledger.jsonは分類・状態管理の初期台帳。92掲載単位と12の列挙済み未収録候補を含むが、本編全品の列挙は未完成。通常カテゴリのuniverseTotal=null、enumerationComplete=false。未収録候補0件は未収録品がないことを意味しない。

旧data/coverage-ledger.jsonも維持。追加で解決した候補はresolvedCandidatesへIDを残して移し、canonicalGuideIdsで参照する。候補と実記事を二重に件数へ足さない。
